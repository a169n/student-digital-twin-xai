## «Объяснимый цифровой двойник студента для аналитики обучения на стороне преподавателя»

---

## 1. О ЧЁМ РАБОТА — в двух предложениях

LMS (Moodle, Canvas) собирают данные об активности студентов, но не предсказывают и не объясняют результаты. Мы построили систему которая еженедельно предсказывает риск каждого студента и объясняет преподавателю **почему** — и честно проверили, стоит ли усложнять модель.

---

## 2. ПРОБЛЕМА И АКТУАЛЬНОСТЬ

| Проблема | Наш ответ |
|---|---|
| LMS-аналитика описывает прошлое, не предсказывает | Еженедельные предсказания риска |
| ML-модели — "чёрный ящик", преподаватель не доверяет | XAI-слой с объяснениями на уровне студента |
| Непонятно, нужны ли сложные фичи или хватит простых | Аблационное исследование A→B→C |
| В литературе мало честных "негативных" результатов | Мы честно публикуем что сложное не помогло |

---

## 3. ПОЧЕМУ "COGNITIVE DIGITAL TWIN", А НЕ ПРОСТО "DIGITAL TWIN"

Обычный digital twin — про физические объекты (турбина, здание): полностью наблюдаем, детерминирован, точная копия состояния.

**Студент — принципиально другой объект:**
- Когнитивный агент с мотивацией, эмоциями, контекстом жизни
- Частично наблюдаем — мы видим только цифровые следы в LMS
- Мы не знаем **почему** студент не зашёл в систему, понял ли материал или просто кликнул
- Наш twin — **приближение когнитивного состояния** через косвенные сигналы

Именно поэтому XAI-слой критически важен — преподаватель должен интерпретировать объяснения с пониманием ограничений.

### Три источника данных

| Датасет | Что это | Для чего |
|---|---|---|
| **Синтетический (наш)** | Сгенерированные данные | Разработка системы (exp_001–004) |
| **OULAD DDD 2013J** | 1 938 студентов, 67 830 снапшотов | Основная валидация |
| **OULAD BBB 2013J** | 2 237 студентов, 80 532 снапшота | Проверка на другом курсе |
| **KU Leuven 1819** | 1 495 студентов (Бельгия) | Другой университет — стресс-тест |

**Гранулярность:** 1 строка = 1 студент × 1 неделя

### Почему еженедельный снапшот, а не ежедневный?
1. Учебный цикл студента — **недельный**: лекция, задание, дедлайн
2. Дневные данные слишком зашумлены (не зашёл в среду — болел? или просто дедлайн в пятницу?)
3. Преподаватель не смотрит дашборд каждый день — еженедельный ритм естественен
4. OULAD сам организован по неделям — позволяет сравниваться с другими работами

## 5. АБЛАЦИОННОЕ ИССЛЕДОВАНИЕ — главный эксперимент

**Аблация** = поэтапно добавляем фичи и смотрим, улучшается ли модель.

### Четыре набора фич

#### A_simple — только оценки
```
avg_assignment_score_to_date   — средняя оценка за задания
avg_quiz_score_to_date         — средняя оценка за квизы
attendance_rate_to_date        — процент посещаемости
has_assignment_score_to_date   — есть ли вообще оценка (булево)
has_quiz_score_to_date         — есть ли оценка за квиз (булево)
```

#### B_lms — добавляем активность в LMS
```
activity_score_to_date              — нормализованная активность (клики)
time_spent_to_date                  — время на платформе (минуты)
on_time_submission_rate_to_date     — доля сданных вовремя
missed_assignments_to_date          — количество пропущенных заданий
late_submissions_to_date            — количество поздних сдач
avg_attempt_count_to_date           — среднее число попыток
```

#### B_lms+mastery — добавляем освоение материала
```
current_topic_mastery   — оценка по теме текущей недели
overall_mastery         — агрегированное освоение всех тем
```

#### C_twin — полный цифровой двойник
```
score_trend_3w       — тренд оценок за последние 3 недели
activity_trend_3w    — тренд активности за 3 недели
attendance_trend_3w  — тренд посещаемости за 3 недели

engagement_index     = 0.40×посещаемость + 0.30×активность + 0.30×своевременность
performance_index    = 0.45×оценка + 0.25×квиз + 0.20×mastery + 0.10×тренд
discipline_index     = 0.50×вовремя + 0.30×без опозданий + 0.20×без пропусков

week_number          — номер текущей недели
```

### Откуда взялись веса в индексах?
Веса **эвристические** — основаны на концептуальной значимости из learning analytics литературы (Hernández-García 2024, Santos & Henriques 2023). Точные веса — открытый вопрос, указанный в документации. Именно поэтому мы запустили аблацию — и она показала что C_twin не даёт стабильного прироста.

### Главный вывод аблации
Переход B_lms → C_twin **почти ничего не даёт**. Усложнение фич не оправдано. Это честный негативный результат.

**Почему это не значит что формулы плохие?**
Все компоненты индексов уже есть в B_lms как сырые переменные. Gradient Boosting сам находит оптимальные комбинации. Если прироста нет — дело не в весах, а в том что OULAD просто не содержит достаточно богатых сигналов.

## 6. ML МОДЕЛИ

### Почему их несколько?
Цель — не найти лучшую модель, а **проверить гипотезу о полезности фич**. Если C_twin не помогает ни линейным, ни ансамблевым моделям — вывод устойчив.

### Какие модели

| Задача | Модели |
|---|---|
| **Регрессия** (предсказать итоговую оценку — число) | Ridge, Random Forest, Gradient Boosting |
| **Классификация** (предсказать Pass/Fail) | Logistic Regression, Random Forest, Gradient Boosting |

| Тип | Зачем |
|---|---|
| Линейные (Ridge, Logistic) | Простые, интерпретируемые, видят прямые зависимости |
| Random Forest | Ансамбль, не переобучается, хорошо без настройки |
| Gradient Boosting | Самый сильный — финальное сравнение |

### Результаты
- Классификация: F1 = 0.85–0.86, ROC-AUC = 0.95 на DDD
- Регрессия: RMSE ≈ 12.6 (ошибка ~12-13 баллов из 100)
- Никогда не получили F1 = 1.0 — значит утечки данных нет

### Что такое RMSE?
Средняя ошибка предсказания в баллах. RMSE = 12.6 → модель ошибается в среднем на 12-13 баллов из 100.

## 7. РАЗБИВКА ДАННЫХ — два вида

Модель нужно проверять на данных которые она **никогда не видела** — иначе она просто запоминает ответы.

### Student-Grouped Split
```
Все 1938 студентов
        ↓
Train 80%  |  Test 20%
студенты 1–1550  |  студенты 1551–1938
(все их недели)  |  (все их недели)
```
Студент либо полностью в train, либо полностью в test.
**Вопрос:** работает ли модель на новых студентах?

### Temporal-Forward Split
```
Все студенты
        ↓
Train              |  Test
недели 1–20        |  недели 21–39
(все студенты)     |  (все студенты)
```
Обучаем на ранних неделях, тестируем на поздних.
**Вопрос:** работает ли модель как система раннего предупреждения?

### Три уровня валидации
```
1. Внутри DDD:   student-grouped + temporal-forward
2. Внутри BBB:   student-grouped + temporal-forward
3. KU Leuven:    другой университет — самый строгий тест
```

## 8. XAI — три механизма

### Механизм 1: Permutation Importance (глобальный)
**Вопрос:** какие фичи важны для модели в целом?

**Алгоритм:**
```
для каждой фичи:
  1. предсказать на тестовых данных → RMSE_исходный
  2. случайно перемешать значения ТОЛЬКО этой фичи между студентами
     (разрушаем связь фичи с результатом, но структуру данных сохраняем)
  3. предсказать снова → RMSE_новый
  4. важность = насколько вырос RMSE
```

Почему перемешиваем, а не удаляем? — удаление ломает модель (ожидает фиксированное число фич). Перемешивание убивает информацию, но сохраняет структуру.

**Результат:** топ фичи по всей модели, для всех студентов.

---

### Механизм 2: Local Perturbation (локальный)
**Вопрос:** почему модель так решила для конкретного студента?

**Алгоритм:**
```
для студента Иванова, для каждой фичи:
  1. предсказать с реальными данными → оценка_исходная (например 45)
  2. заменить одну фичу на медиану по всем студентам
  3. предсказать снова → оценка_новая (например 58)
  4. вклад = 45 - 58 = -13 (фича тянет вниз на 13 баллов)
```

**Пример для преподавателя:**
```
Студент Иванов — предсказано 45/100 — ВЫСОКИЙ РИСК

Что снижает оценку:          Что поднимает оценку:
❌ activity_score   -13 pts  ✅ assignment_score  +2 pts
❌ attendance_rate  -7 pts
```
→ Проблема не в знаниях, а в вовлечённости. Нужно выяснить почему не заходит в систему.

---

### Механизм 3: Kendall τ (стабильность объяснений)
**Вопрос:** можно ли доверять этим объяснениям?

Если модель объясняет себя по-разному на разных разбивках данных — преподаватель не может доверять объяснениям.

**Алгоритм:**
```
ranking_1 = [activity, assignment, attendance, ...]  ← student-grouped
ranking_2 = [assignment, activity, mastery, ...]     ← temporal-forward

τ = насколько похожи два ранжирования?
τ = 1.0  → полностью одинаковые → доверять можно
τ = 0.0  → случайные
τ = -1.0 → полностью обратные
```

**Наши результаты:**

| Сравнение | B_lms | C_twin |
|---|---|---|
| Внутри DDD (SG vs TF) | 0.79 | 0.55 |
| Между когортами (SG) | 0.54 | 0.47 |
| Между когортами (TF) | 0.61 | 0.32 |

Порог доверия = **0.90** — мы его не достигли нигде. Объяснения читаемы, но нестабильны между режимами.

### Итог XAI
```
Permutation Importance  →  "какие фичи важны для модели?"        (глобально)
Local Perturbation      →  "почему этот студент в зоне риска?"   (локально)
Kendall τ               →  "можно ли доверять объяснениям?"      (мета-уровень)
```

#### Дашборд когорты (`/dashboard`)

- Распределение риска: сколько High / Medium / Low

#### Профиль студента (`/students/[id]`) — главная страница
**9 метрик карточками:**
```
Предсказанная оценка | Реальная оценка  | Risk score
Overall mastery      | Activity score   | Attendance
Assignment average   | Quiz average     | 3-week trend
```

**График траектории** — 4 линии по неделям:
- Синяя: предсказанная оценка
- Бирюзовая: mastery
- Оранжевая: activity score
- Красная: risk score

**XAI Панель объяснений:**
```
Что поднимает оценку:        Что снижает оценку:
✅ assignment_score  +3.2    ❌ activity_score  -13.0
✅ mastery           +1.8    ❌ attendance       -7.0
```
Каждый фактор: реальное значение студента vs медиана + горизонтальный бар.

**What-If панель (контрфактический анализ):**
> "Если activity_score вырастет до медианы → оценка 45 → 50.5 (+5.2 балла)"

#### Админ-панель (`/admin`) — для исследователя
- Метрики модели (F1, ROC-AUC)
- Глобальная важность фич (permutation importance)
- Все XAI-кейсы
- Провенанс данных (откуда данные, версия схемы)
- Честные ограничения модели и дисклеймеры

### Архитектура
```
ML pipeline (Python)  →  экспортирует JSON/CSV  →  Next.js фронтенд
модели, XAI, аблация     артефакты                  визуализирует преподавателю
```
Фронтенд **не считает модели** — он визуализирует результаты ML pipeline.

## 11. ВАЖНЫЕ ДЕТАЛИ ИЗ СТАТЬИ (которые могут спросить)

### Почему не SHAP, а свой метод XAI?

SHAP — популярный метод, но мы намеренно его не использовали:

- SHAP требует "фоновый набор" (background set) — на маленьких выборках одного студента это ненадёжно
- У SHAP задокументированные проблемы как меры важности фич [Kumar et al. 2020, Slack et al. 2020]
- Наш метод (local median-replacement) работает напрямую на одной строке предсказания — без фоновых допущений

### Synthetic circularity — задокументированный failure mode

Во время разработки обнаружили ловушку:

- Синтетический `final_grade` — это детерминированная формула из тех же фич что модель использует
- Корреляция = 1.000000, R² ≈ 0.99, F1 = 1.000 на синтетике
- Это не настоящий сигнал — алгебраический артефакт (модель просто обращает формулу)
- На реальных данных OULAD такого нет — F1 никогда не равен 1.0

> **На защите:** "Мы намеренно включили это в статью — это методологический вклад. Синтетические данные с циклическим таргетом могут симулировать победу метода которой на самом деле нет."

### Частичная цикличность на OULAD

`final_weighted_score` частично зависит от оценок за задания — тех же что входят в фичи. Поэтому:

- Классификация (Pass/Fail) и VLE-клики — более чистые независимые сигналы
- Регрессионные результаты немного "облегчены" этим — это ограничение, мы его признаём

### Mastery ≈ assignment_score

`overall_mastery` коррелирует с `avg_assignment_score` на уровне |r| = 0.993. Это почти одна и та же переменная — mastery не является независимой конструкцией.

### Bootstrap подтверждение единственного положительного результата

BBB temporal-forward mastery дал −1.026 RMSE. Проверили что это не случайность:

- 5000 bootstrap resample итераций
- 95% CI полностью ниже нуля: [−2.54, −1.80]
- P(delta ≥ 0) = 0.000 — направление не шум
- Но magnitude чувствительна к режиму — "одна ячейка где Twin помогает", не стабильный эффект

### KU Leuven — особый случай

- Нет промежуточных оценок вообще — только клики и бинарный PASSED
- Аблацию mastery там вообще нельзя построить — само по себе cross-institution heterogeneity result
- На engagement-only: F1 0.75–0.76, ROC-AUC 0.65–0.72
- Два простых признака (клики + активные дни) невозможно побить богатым набором

### Точность нашей системы vs литература

| Система | F1 | ROC-AUC | XAI | UI | Открытая |
|---|---|---|---|---|---|
| Наша (GB + Twin + XAI) | 0.861 | 0.953 | Да (perturbation) | Да | Да |
| Лучшая в литературе [4] | 0.911 | 0.993 | Да (SHAP) | Нет | Частично |
| Коммерческие (EAB Navigate) | неизвестно | неизвестно | Частично | Да | Нет |

Мы ниже лучшей в литературе по точности — это ожидаемо и не слабость. Наш вклад — полный цикл от сырых данных до UI с честной оценкой.

## 12. СЛОЖНЫЕ ВОПРОСЫ И КАК ОТВЕЧАТЬ

**"Почему веса в индексах такие, а не другие?"**
> Веса эвристические, основаны на литературе по learning analytics. Точные веса — открытый вопрос. Аблация показала что C_twin не даёт прироста — значит вопрос весов не принципиален для вывода.

**"Может плохие формулы и стали причиной отсутствия роста?"**
> Маловероятно — все компоненты индексов уже присутствуют в B_lms как сырые переменные. Gradient Boosting сам находит оптимальные комбинации. Более вероятно — OULAD просто не содержит достаточно богатых сигналов для Twin-фич.

**"Почему несколько моделей?"**
> Чтобы сравнивать наборы фич честно. Если C_twin не помогает ни линейным, ни ансамблевым моделям — вывод устойчив.

**"Почему еженедельно, а не ежедневно?"**
> Учебный цикл студента недельный. Дневные данные зашумлены. Преподаватель не смотрит дашборд каждый день.

**"Это честный digital twin?"**
> Это cognitive digital twin — приближение когнитивного состояния через косвенные сигналы. Мы видим только цифровые следы в LMS, не реального студента. Поэтому XAI-дисклеймеры обязательны.

**"Почему результат негативный — это ценно?"**
> Воспроизводимые, честные негативные результаты под-представлены в литературе по learning analytics. Мы показали что feature richness не помогает — и это важное знание для поля.
