# Направления будущей работы / Future Work

## Почему текущая система ограничена

Главный вывод диссертации: на данных уровня OULAD (клики + оценки) Twin-фичи не дают стабильного прироста над LMS-базисом. Причина не в ошибке реализации — причина в том что OULAD слишком беден для раскрытия потенциала цифрового двойника.

Три направления которые устранят это ограничение:

---

## Направление 1 — Богатые данные

### Проблема
OULAD даёт только число кликов и итоговую оценку. Twin-фичи (тренды, индексы) являются детерминированными функциями тех же переменных что уже есть в B_lms — новой информации они не несут.

### Что нужно собирать

| Сигнал | Почему важен |
|---|---|
| Время просмотра видео (секунды) | Клик ≠ просмотр. 2 секунды vs 20 минут — разный engagement |
| Форумная активность | Написал вопрос? Ответил другому? Качество взаимодействия |
| Траектория попыток | Сдал с 3-й попытки vs с 1-й — разный уровень освоения |
| Текст эссе / открытых ответов | NLP-анализ качества, а не только оценка |
| Временны́е паттерны | В 2 ночи перед дедлайном vs равномерно — разная дисциплина |

### Ожидаемый эффект
С такими данными `score_trend_3w` и `engagement_index` несли бы **новую** информацию которой нет в сырых переменных. Twin получил бы реальное преимущество.

### Публичные датасеты которые стоит попробовать
- **MOOC datasets** (Coursera, edX) — богаче OULAD по типам активности
- **Khan Academy dataset** — детальные логи взаимодействия с задачами
- **ASSISTments** — детальные данные по попыткам решения задач

## Направление 2 — Временны́е модели

### Проблема
Gradient Boosting видит **один снапшот** — одну строку таблицы за одну неделю. Он не понимает последовательность. Паттерн "три недели падал → резко вырос" для него невидим.

### Что применить

**LSTM / GRU (Long Short-Term Memory)**
- Специально разработаны для последовательностей
- Запоминают паттерны за несколько временны́х шагов
- Вход: последовательность еженедельных снапшотов студента
- Умеют: "этот студент падает уже 4 недели подряд — высокий риск"

**Transformer (self-attention)**
- Видит всю траекторию студента целиком
- Может взвешивать важность разных недель
- Например: неделя перед экзаменом важнее недели 3

**Hidden Markov Model (HMM)**
- Моделирует скрытые состояния студента
- Например: активен → пассивен → восстановился → критическая зона
- Переходы между состояниями дают сигнал для вмешательства

### Конкретный пример где это помогло бы
```
Неделя:    1    2    3    4    5    6    7    8
Оценка:   75   72   68   61   55   49   44   40

GB видит:  только неделю 8 → оценка 40, предсказывает риск
LSTM видит: устойчивый нисходящий тренд с недели 1 → предупреждает раньше
```

### Что нужно для реализации
- Рефакторинг пайплайна: вход = последовательность, не один снапшот
- Больше данных на студента (OULAD достаточен по числу недель)
- Валидация: сравнение с текущим GB на тех же данных

## Направление 3 — Item Response Theory (IRT) для честного Mastery

### Проблема
Наш `overall_mastery` коррелирует с `avg_assignment_score` на уровне |r| = 0.993. Это почти одна и та же переменная — mastery не является независимой конструкцией и не несёт новой информации.

### Что такое IRT
Психометрический метод который оценивает **реальный уровень знаний** с учётом сложности заданий:

```
Обычный mastery (наш):
  решил 8 из 10 заданий → mastery = 80%

IRT mastery:
  решил 8 лёгких из 10 лёгких    → реальный уровень = ~55%
  решил 8 сложных из 10 сложных  → реальный уровень = ~90%
```

IRT учитывает:
- **Сложность задания** — лёгкое или сложное
- **Дискриминативность** — насколько задание различает сильных и слабых
- **Угадывание** — вероятность угадать правильный ответ

### Почему это даст прирост
IRT-mastery был бы **истинно независимой** конструкцией от среднего балла. Gradient Boosting получил бы реально новую информацию — не переформулировку той же оценки.

### Что нужно для реализации
- Библиотека: `girth` или `mirt` (R) / `pyirt` (Python)
- Данные: нужны множественные попытки на одни и те же задания разными студентами
- OULAD частично подходит — есть TMA/CMA с весами и типами

## Направление 4 — Пользовательское исследование (User Study)

### Проблема
Текущий интерфейс — **design demonstrator**. Мы показываем что XAI-объяснения технически работают, но не знаем:
- Понимают ли преподаватели объяснения правильно?
- Принимают ли они лучшие решения о вмешательстве?
- Не вводят ли дисклеймеры в замешательство?

### Что сделать
- Качественное исследование с 5–10 преподавателями (think-aloud protocol)
- Количественный эксперимент: группа с системой vs группа без → сравнить ранние вмешательства
- Измерить: понимание объяснений, доверие к системе, изменение поведения

### Почему это важно
Без user study нельзя утверждать что система **реально помогает** преподавателям. Сейчас мы честно говорим что это demonstrator — следующий шаг это доказать эффект.
