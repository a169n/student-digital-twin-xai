# Architecture Overview

## Research Positioning

`student-digital-twin-xai` is a research prototype for teacher-oriented educational analytics. The system centers on a dynamic **student digital twin** used for prediction, interpretation, and intervention planning.

## Core Principles

1. **Teacher-first decision support**: outputs must be actionable for instructional intervention.
2. **Digital Twin as a stateful representation**: not a static BI dashboard.
3. **XAI-by-design**: risk and grade predictions must be interpretable.
4. **Evolvable contracts**: schema versions are explicit and intentionally changeable.
5. **Modular monorepo**: isolate concerns while sharing contracts.

## System Boundaries (Current)

- In scope: teacher-facing research workflow, local application persistence,
  read APIs, frozen artifact import, prediction/explanation inspection.
- Out of scope: production LMS integration, auth/roles, live retraining,
  institutional deployment hardening, finalized intervention management.

## High-Level Components

- Web app (Next.js): teacher-facing research platform UI.
- API app (FastAPI): domain read APIs and local application projection.
- Application store (SQLite): generated local persistence under
  `data/application/`, seeded from frozen research payloads.
- ML service (Python): dataset generation, experiments, inference artifacts,
  explainability artifacts, and deterministic export scripts.
- Contracts package: versioned schema and cross-service structures.

## Current Data Flow

1. Synthetic LMS-like data and processed Twin snapshots are generated by the ML
   service under `data/raw/` and `data/processed/`.
2. Frozen experiments write evidence under `data/artifacts/experiments/`.
3. `services/ml/src/export/export_research_demo_payload.py` reshapes frozen
   evidence into `data/artifacts/research_demo/research_demo_payload.json`.
4. The API importer reads that payload into
   `data/application/research_platform.sqlite`.
5. FastAPI serves teacher-facing dashboard, student, Twin, prediction,
   explanation, and research evidence endpoints.
6. Next.js consumes those endpoints at runtime.

This projection does not change `schema_v1.2` and does not rerun or overwrite
prior experiments.
